# 06 git 基本原理（简洁版）

## 一句话总结

git = 项目的"存档系统 + 时间机器"。

## 三个区 + 一条操作链

```
工作区（你改文件的地方）
    │
    │ git add 文件名（挑进暂存区）
    ▼
暂存区（待提交的修改）
    │
    │ git commit -m "说明"（正式存档）
    ▼
本地仓库（已存档的版本记录）
    │
    │ git push（上传到 GitHub）
    ▼
远程仓库（GitHub 云端备份）
```

## 分支是什么？

- 分支 = 指向某个 commit 的"指针"（书签）
- 新分支创建时 = 复制当前分支的最新 commit 指向
- 在不同分支上各自 commit → 两本书签分叉到不同位置
- 分支之间互不影响，因为每个 commit 保存了独立快照

## git 如何省空间？

- 不是每个版本都复制一份文件
- 相同内容的文件只存一份（去重）
- 改得少的文件只存"差异（增量）"
- 用 zlib 压缩所有对象
- 所以 .git 文件夹通常比工作区文件还小

## 为什么提交后的文件才互不影响？

- 未提交的修改存在工作区，不属于任何分支
- 切换分支时，未提交的修改会跟着跑（因为没被 git 快照隔离）
- 一旦 commit，修改被固定到该分支的快照里，彻底隔离
- 习惯：改完就 commit，再切分支

## 核心习惯

1. 改完就 commit，让改动有归属
2. 切分支前先 `git status` 确认没有未提交修改
3. 用 `git commit -am "说明"` 简化已跟踪文件的提交
4. `.gitignore` 管好不想提交的文件
